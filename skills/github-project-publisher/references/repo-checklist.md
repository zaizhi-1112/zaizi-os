# Repo Checklist

Use this checklist before calling a GitHub publishing job complete.

## Structure
- project lives in a focused directory
- unrelated workspace files are excluded
- repository has a clear top-level structure

## Docs
- README exists
- project description exists if needed
- short repo description exists if needed
- submission copy exists if needed
- usage example exists if needed

## Git
- git repo initialized
- initial commit created
- main branch set
- remote origin configured
- push successful

## Presentation
- repo name matches the actual project
- README clearly explains the project
- packaged outputs are included if useful
- optional cover image/hero asset exists

## Completion test
If someone opens the repo for the first time, they should understand:
- what this project is
- why it exists
- what is included
- how to use or evaluate it
