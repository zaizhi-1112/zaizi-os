# Memory Hygiene

Use this reference to decide what belongs in durable memory versus what should stay ephemeral.

## Store in durable memory

Store:
- stable preferences
- naming conventions
- recurring collaboration rules
- long-term project context
- explicit “remember this” requests
- important lessons from repeated mistakes
- identity-level facts that shape future interactions

Examples:
- “When I am only syncing status, do not default to copywriting mode.”
- “Use these five labels: 同步 / 快答 / 分析 / 执行 / 存档.”
- “The assistant should sound direct, grounded, slightly sharp, but not mean.”

## Do not store in durable memory

Do not store:
- every conversation turn
- raw transcript fragments without future value
- one-off logistics with no lasting relevance
- emotional moments that do not create a lasting preference or agreement
- redundant restatements of what is already saved elsewhere

## Distillation rule

Save the distilled agreement, not the whole story.

Bad:
- Long raw explanation of why the user was annoyed one night

Good:
- “User prefers the assistant to acknowledge status sharing instead of immediately generating copy.”

## Storage hierarchy

When in doubt, classify information into one of four buckets:
1. live thread only
2. phase summary
3. durable memory
4. dedicated project file

Prefer the lightest bucket that preserves future usefulness.
