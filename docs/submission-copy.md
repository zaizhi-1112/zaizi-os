生产力龙虾

## 项目描述
崽子 OS 是一个基于 OpenClaw 搭建的长期协作型 AI 员工系统。它不只是一个“能聊天”的助手，而是一个能够在长期使用中持续保持角色一致性、沟通效率、上下文连续性与自我校准能力的个人生产力系统。

在真实使用过程中，我围绕自己的工作流，逐步把 OpenClaw 从一个即时对话工具，打磨成一个能够长期协助我进行内容运营、工作复盘、效率监督、模型切换、知识沉淀与 skill 封装的 AI 员工。

这个项目重点解决了几个长期使用 AI 助手时非常真实的问题：
- 聊久了之后上下文越来越重，效率越来越低
- 助手容易变得模板化、失去原本的人格与协作感
- 沟通意图不清晰，导致误判、过度输出和重复返工
- 解决过的问题容易停留在聊天记录里，无法沉淀为可复用能力

为了解决这些问题，我构建了几层关键能力：
1. 高效沟通协议：通过【同步 / 快答 / 分析 / 执行 / 存档】五种用途标签，降低误判和上下文膨胀。
2. 长期连续性系统：将即时会话、长期记忆、协作协议、自我校准分层管理，让 AI 助手长期使用后仍然稳定、轻量、可持续。
3. 自我校准机制：当助手逐渐变得像“标准助手”、失去角色感时，能够识别并拉回正确的人格与表达方式。
4. Skill 机会雷达：在长期协作中，自动识别哪些重复解决的问题、哪些高价值结果以及哪些已经完成资产化的工作流值得沉淀成 skill，避免经验只留在聊天记录里。
5. GitHub 项目发布工作流：把一个本地项目从零整理成可上传的 GitHub 仓库，包括仓库结构、README、补充文档、git 初始化、远程仓库推送与常见报错排查。
6. 模型切换、短回复保护与重试防护：在模型切换、gateway 重启、会话恢复等不稳定窗口里，主动进入短回复保护模式，减少重复回复、半截重发和额外消耗。
7. 效率监督能力：结合真实工作周报和复盘结果，逐步让助手具备提醒、监督和纠偏我的工作节奏与执行习惯的能力。

这个项目想证明的不是“AI 可以做很多事”，而是：
**AI 助手在长期协作场景下，如何从一次性工具，进化成真正能长期陪跑、持续提效、不断沉淀方法的个人生产力操作系统。**
